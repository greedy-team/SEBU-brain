# SEBU AI 검증과 도입 과제

기획서는 7주 동안 수집·요약·연구실 연결을 만들고 품질·서버 부하·사용자 반응을 확인하는 계획을 제시한다. 아래 항목은 수행 결과가 아니라 착수와 검증에 사용할 계획이다.

## 기획서의 추진 일정

| 단계 | 예정 주차 | 내용 |
|---|---|---|
| 기획 | 1주 | 요청량·요구사항 정리 |
| 분석 | 1~2주 | 기사 이용 조건·연구 분야 검토 |
| 설계 | 2~3주 | 응답 형식·DB·화면·지표 설계 |
| 개발 | 3~5주 | 수집 → AI → 연구실 연결 구현 |
| 테스트 | 5~6주 | 요약 정확도·매핑·서버 부하 확인 |
| 완성 | 7주 | 사용자 검토·반영·운영 문서 정리 |

기준 시작일·담당자·실제 완료일은 원문에서 확정하지 않았다. 달력 날짜나 진행률을 임의로 부여하지 않는다.

## 품질과 운영 검증

| 확인할 문제 | 기획서의 대응·검증 계획 |
|---|---|
| 기사 수집 적합성 | 기사·사진의 이용 조건과 출처 표시 확인, 정치적 주장·정당·선거 중심 글 제외 |
| 요약 형식·사실성 | 필수값과 세 문장 여부 검사, 초기 10~20건 원문 대조 |
| 연구실 연결 오류 | 분야 ID 존재 확인, 관련 근거 확인, 근거 없으면 연결 결과 미노출 |
| 서버 부하·API 한도 | 외부 API 호출, 순차 처리, 결과 재사용, 개발 서버 메모리·기존 API 응답 시간 측정 |
| 중복 수집·실패 | URL 고유 제약, 실패 기록, 수집 주기 조정, 429 제한 재시도 |
| 화면 활용 | 기사 카드에서 관련 분야·연구실 상세·후기로 이동하는 흐름을 사용자 의견으로 개선 |

## 효과를 확인하는 방법

원문은 **기사에서 연구실로 이동하는 비율과 재방문율을 도입 전후 비교**하고, 기존 검색·커뮤니티 활용이 늘어나는지 확인하려 한다. 이를 위해 방문·클릭 이벤트를 요청량과 분리해 수집한다.

API 요청 수는 사람 수나 재방문율이 아니다. 방문자 식별 기준, 비교 기간, 클릭 비율의 분모, 재방문으로 인정할 기간과 목표치는 원문에 정해져 있지 않으므로 지표 설계에서 확정해야 한다. 새로 7일 재방문율 등의 조건을 확정 요구사항으로 추가하지 않는다.

[[SEBU 구현 현황]]에 기록된 FE GA4 PR #180은 2026-10-26 기준 Draft·미병합이다. 이것을 AI 도입 효과 지표가 이미 수집된다는 근거로 사용하지 않는다. [[SEBU 운영 모니터링과 대시보드 해석]]

## 개발 전에 확정할 항목

아래는 원문에 미정으로 남아 있거나 구체적인 계약이 없어 추가 설계가 필요한 항목이다.

- [ ] 실제 수집 매체·기사 범위·사진 이용 조건과 화면 출처 표시.
- [ ] Gemini 모델명, 사용 가능한 티어·호출 한도·비용 상한.
- [ ] 요약·키워드·분야 ID·연결 이유의 JSON Schema, DTO와 API 계약.
- [ ] 기사·처리 결과·분야 연결·출처 저장 구조, 중복 URL 정책과 마이그레이션.
- [ ] 후보 연구 분야의 설명·동의어 검수와 관련성 판단 기준.
- [ ] 수집 주기·건수, 본문 크기·시간 제한·재시도 횟수와 실패 기록 방식.
- [ ] 화면 예시의 탭·저장·피드백 버튼 포함 여부와 FE 연결 범위.
- [ ] 품질·부하 허용 기준, 방문·클릭·재방문 지표의 정의와 도입 전 기준값.

## 팀 지식으로 남길 결과

수집부터 Gemini 호출·JSON 검증·DB 저장·화면 연결까지의 결정과 테스트 결과를 이 영역에 갱신한다. 원문이 제시한 기대효과에는 AI 기능 개발 경험, 운영 서비스 문제 해결, AI 코딩 도구가 참고할 세컨 브레인 축적, 요약 오류 검수 경험도 포함된다.

현재 단계는 기획서 지식화다. 실행한 테스트·구현 PR·운영 배포 기록이 생기기 전까지 완료로 표시하지 않는다.
