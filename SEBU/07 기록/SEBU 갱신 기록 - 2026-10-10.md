# SEBU 갱신 기록 - 2026-10-10

## 코드 기준과 실행 기록

- BE 코드 기준은 develop [7d4839b](https://github.com/greedy-team/SEBU-backend/commit/7d4839b46ca8cdc6c608ec9934ee02e018e54893)다. 지난 기준 bb73725 이후 V51 SQL·테스트·검수 CSV 등 5개 파일이 추가됐다.
- BE 운영은 main [3c7445e](https://github.com/greedy-team/SEBU-backend/commit/3c7445e173528b22c40c9abb47b0fb35ad81ff6e)이며 확인한 develop과 파일 트리가 같다. PR #98·#99의 코드 반영과 실제 운영 API 반영을 구분해 기록했다.
- FE 원격 dev는 [e7e54de](https://github.com/greedy-team/SEBU-frontend/commit/e7e54deff631adfef08b9b9e0dac9af5c398c317)로 지난 기준과 같다. 이번 갱신은 FE 코드 수정·배포 작업이 아니다.
- 모니터링은 기존 코드의 기능을 운영 환경에서 활성화한 작업이다. 신규 애플리케이션 커밋이나 DB 마이그레이션을 만든 것으로 기록하지 않는다.
- 운영 상태와 CPU·메모리·요청량 수치는 확인 시점의 관측값이다. 문서에 적힌 값이 이후에도 고정된다고 가정하지 않고 실시간 대시보드에서 확인한다.

## 완료로 취급하지 않은 항목

현재 대시보드는 백엔드의 지표 수집, HTTP 응답, JVM과 DB 연결 풀을 본다. 실제 학교 로그인·후기 작성 같은 사용자 시나리오의 성공, EC2 전체 메모리·디스크, 로그 전송, 백업 실패 알림, 사용자 수 집계까지 확인하는 구성은 아니다.

알림 규칙·연락처·Normal 상태와 타깃 부재 시 쿼리 결과는 검증했지만, 운영 서버를 의도적으로 중단하거나 실제 장애 이메일 수신을 시험하지 않았다. 기존 로그인 1시간 고정 만료·연장 모달·서비스 내부 신고와 관리자 기능도 여전히 별도 요구사항이다.

## 문서 검증과 보존 원칙

이번 갱신은 원격 커밋과 이미 확보한 운영 실행 증거를 대조했다. 브레인 갱신 과정에서는 운영 DB 변경·재배포·로그인 시험을 수행하지 않는다. V51의 30개 마이그레이션 테스트와 모니터링 활성화 도구의 24개 테스트는 해당 작업의 기존 실행 결과이며, 이번 문서 검사와 구분한다.

새 노트에서 근거까지 이동할 수 있도록 연결하고, 현재 구현 근거는 source-baseline에 새 코드 기준으로 기록한다. 날짜가 붙은 과거 기록의 내용과 당시 커밋 링크는 고정해 최신 기준으로 덮어쓰지 않는다. 비밀 토큰·환경 파일·DB 백업·회원 데이터·개인 절대 경로는 공유 문서에 넣지 않는다.

문서 검증은 `npm run sources:record -- --reviewed`, `npm run check`, `npm test`, `npm run sources:check`로 수행한다. 검사 결과는 이 갱신의 PR에 남긴다. 구조 검사가 문장의 의미나 모든 서비스 기능의 정상 동작까지 자동 보증하지는 않는다.
