# SEBU 갱신 기록 - 2026-10-26

**GitHub 최신 원격을 확인한 결과, 병합된 BE·FE 코드는 기존 문서 기준과 같았다.** 로컬 비교용 저장소를 최신 커밋으로 맞추고, 새로 확인한 미병합 GA4 초안과 남은 검증을 문서에 반영했다. 운영 서버 재배포·DB 변경·FE 구현은 수행하지 않았다.

세 저장소에서 원격 갱신 후 확인했다. 로컬 비교용 BE develop은 `b6cf2e5 → 7d4839b`, FE dev는 `88eee80 → e7e54de`로 fast-forward했다. 이 차이는 비교용 체크아웃이 뒤처져 있던 것이며, 오늘 GitHub에 새 기능이 병합됐다는 의미가 아니다.

별도 FE 작업 폴더의 미커밋 변경·분기 이력과 기존 브레인 초안은 보존했다. 개인 경로나 미커밋 코드를 공유 근거로 사용하지 않는다.

### GA4 초안의 의미

PR #180의 head는 `feat/ga4-consent-analytics`의 [cdf2b6b](https://github.com/greedy-team/SEBU-frontend/commit/cdf2b6bac909f3c52b59e25e94f097da083a6335)이며, 패치에서는 App.jsx 한 파일만 변경한다. 운영 빌드의 www.sebu.kr에서 명시적 선택 동의 후 GA4를 불러오고, SPA 페이지 조회를 보내며 쿼리·해시·유입 주소와 동적 경로 식별자를 제거하려는 코드다. 거부·철회와 브라우저 추적 거부 신호 처리도 초안에 있다.

이는 패치와 PR 설명을 확인한 결과이며 실제 동작 검증을 완료했다는 뜻이 아니다. PR에 남은 실제 빌드, 브라우저 네트워크, 동의·철회·SPA 동작, GA4 수신과 보관 설정 검증을 그대로 대기 항목으로 남긴다. 개별 방문자 수는 동의하고 측정 가능한 범위이며 전체 회원·실시간 접속자·API 요청 수와 구분한다.

현재 운영 dev에는 이 초안이 병합되지 않았으므로 GA4 수집 완료나 사용자 수 대시보드 구축 완료로 기록하지 않는다. [[SEBU 운영 모니터링과 대시보드 해석]]

## 현재 코드에서 다시 확인한 내용

- BE 배포 채널은 main·develop이며, 이미지 게시 후 서버에서 Pull하는 기존 구조다.
- FE vercel.json의 API 목적지는 `https://api.sebu.kr/api/:path*`다. FE dev가 운영 브랜치라는 팀 방침을 유지한다.
- BE 인증 설정 기본값은 Access 30분·Refresh 12시간·절대 세션 30일이다. 1시간 고정 만료·연장 안내 모달을 구현한 것으로 바꾸지 않는다.
- FE 연구 분야 칩은 categories 배열을 순회하며 parentId에 따른 부모·자식 그룹을 구성하지 않는다. 계층 UI는 남은 작업이다.
- 서비스 내부 신고·관리자 기능과 실제 학교 로그인·인증된 쓰기 수용 검증은 기존 미완료 목록을 유지한다. [[SEBU 변경 검토 목록]]

## 운영 기록을 읽는 기준

운영 배포·연구 정보 이관·초기 및 정기 백업·V50·V51 홈페이지 보완·Grafana 구축은 [[SEBU 운영 배포 완료 기록 - 2026-10-09]]와 [[SEBU 운영 모니터링 구축 기록 - 2026-10-10]] 등 당시 실행 증거를 따른다. 연구실 622개와 알림 Normal 같은 과거 관측값을 10월 26일의 실시간 결과로 재사용하지 않는다.

이번에는 EC2·DB·S3·Grafana·Vercel의 실제 런타임 상태, 최신 회원·후기 수, 학교 계정 로그인과 인증된 쓰기를 다시 검사하지 않았다. 코드 브랜치가 같은 것과 현재 실행 환경이 정상인 것은 별도 확인 사항이다.

## 문서 반영과 검증 범위

구현 현황·기준 버전·변경 검토 목록·모니터링 안내·README·홈·지식 지도·목록을 연결하고 기준 확인일을 갱신했다. 과거 날짜의 운영·갱신 기록은 보존했다. 개인 공부·시험·번역 등 SEBU와 무관한 대화는 이번 프로젝트 문서에 반영하지 않았다.

검증은 source 기준 대조, `npm run sources:record -- --reviewed`, `npm run check`, `npm test`, `npm run sources:check`로 수행한다. 문서 검사는 실제 서비스 기능 테스트와 구분한다.
