## 연구분야 분리와 카테고리 매핑

구분자만으로 나누지 않고 의미 단위를 확인했다. 이기정의 영어 나열은 세 분야, 위정민의 소개는 여섯 분야, 강유원의 `체육원리 현상학`은 두 분야, 김형남의 소개는 세 분야로 수동 분리했다. `인공지능과 패션 디자인`, `예술/디자인사`, `뉴미디어 공연/영상콘텐츠` 같은 복합 표현은 유지했다. `제작`은 원문 이름을 보존하고 같은 분야로 재사용했다.

기존 `DESIGN_ARTS`, `HISTORY_CULTURE`, `POLICY_MANAGEMENT`, `AI_ML`, `HCI_XR`를 재사용했다. 기존 분류로 충분히 표현하기 어려운 음악·공연과 체육에는 최상위 카테고리 2개를 추가했다. 표시 순서는 현재 최댓값 다음으로 배정한다.

| 코드 | 이름 | 분류 범위 |
| --- | --- | --- |
| `MUSIC_PERFORMING_ARTS` | 음악·공연예술 | 기악·성악·음악문헌·무용·연기·공연예술 교육 |
| `SPORTS_PHYSICAL_EDUCATION` | 체육·스포츠 | 체육학·체육원리·스포츠철학·신체문화 |

분류는 검색을 위한 검수 판단이다. 분야명과 원문 문맥을 함께 보았고, 복수 의미가 명시된 분야는 여러 카테고리에 연결했다. `질적연구`는 해당 교수의 체육철학·인문학적 방법론 문맥을 근거로 `HISTORY_CULTURE`에 연결했다. 기존 전역 분야명·분류를 바꾸거나 삭제하지 않았다.

55개 분야 중 기존 `영화`와 그 `DESIGN_ARTS` 매핑을 재사용한다. 따라서 새로 추가되는 값은 분야 54개, 연구실 연결 61개, 카테고리 2개, 분야–카테고리 연결 68개다. 전체 카테고리는 52개에서 54개가 되며 V47의 로봇 하위 분류와 기존 부모 관계는 보존한다.

## 배포와 검증

`V48__import_reviewed_arts_sports_professors.sql`은 기존 V42 학과 ID를 찾아 출처와 누락된 교수·연구실·소속 연결을 추가한다. `V49__import_reviewed_arts_sports_research_fields.sql`은 교수 이메일·이름과 기존 활성 연구실을 찾아 분야·카테고리·연결을 추가한다. 숫자 ID를 고정하지 않는다. 기존 프로필, 수동 홈페이지, 공식 연구실명, 모집 상태, 연구분야 연결은 덮어쓰지 않는다. 신원·출처·연구실·카테고리 충돌은 본 테이블 기록 전에 차단한다.

격리된 H2 DB에서 기존 서비스로 6개 URL을 다시 수집해 18개 후보를 원문 스냅샷과 대조한 뒤 승인·승격했다. 교수·연구실 각 18개가 생성됐고 재승격 대상은 0개였으며, 기존 교수·연구실 각 303개는 그대로 유지됐다. 승격값과 검수 CSV 144개 필드도 모두 일치했다.

연구분야도 기존 추출·수동 분리·승격 서비스를 격리된 H2에서 실행했다. 자동 후보 52개에서 네 항목을 14개 자식 후보로 나누고, 원래 분리 대상 네 항목과 목록 번호 한 항목을 제외했다. 최종 61개를 승인·승격하여 분야 54개와 연구실 연결 61개를 생성했다. 재승격 대상은 0개였으며 기존 프로필·분야·연결·카테고리·검수 상태를 보존했다.

이 승격 DB에 V49를 적용해 카테고리 2개와 분류 연결 68개만 추가되는 것도 확인했다. 최종 연구실 연결 61개·분류 연결 69개가 검수본과 일치하고, 이미 승격된 분야·연결·후보 이력과 기존 카테고리·매핑은 그대로 유지됐다.

계약 테스트는 기존 단과대와 같은 방식으로 빈 DB 전체 마이그레이션, V47→V48 및 V48→V49 업그레이드, DB 건수·대표값·연결·기존 데이터 보존·충돌 거절·SQL 재실행을 검증한다. 분야 테스트는 Hibernate 스키마 검증, 실제 JPA를 통한 카테고리 응답·연구실별 분야·카테고리 조회도 확인한다. 기존 수동값이 있는 업그레이드는 원문으로 덮어쓰지 않고 보존 전후 값을 비교한다. 원문과 CSV의 전수 대조는 수집 작업 중 수행한 검수 기록으로 남기며, 예체대 계약 테스트는 CSV 파일을 읽지 않는다.

이전 검수 커밋 `5ad6488`에서 교수·연구실 계약 16건(H2 8 + MySQL 8), 연구분야 계약 20건(H2 10 + MySQL 10), 전체 비Docker 회귀 620건이 통과했다. 실패·오류·스킵은 0건이었다. 이후 문서 분리와 함께 CSV 의존 테스트를 기존 단과대의 DB 검증 방식으로 통일했다.

변경 후 `48e4bdf` 기준으로 H2 18건과 실제 MySQL 8.0.45 18건, 총 36건을 다시 실행해 모두 통과했다. 실패·오류·스킵은 0건이며, 연구실 18개의 `교수명 교수님 연구실`·`GENERATED`도 DB에서 확인했다. 마이그레이션과 애플리케이션 코드는 변경하지 않았다. SEBU-brain 문서 검사와 도구 테스트 5건, 스킬 구조 검증도 통과했다. 이전 CSV 5개와 이관본은 바이트 단위로 동일하다.

승인 이력은 격리된 검수 DB에 남겼다. 교수 후보 18건과 분야 후보 61건을 `APPROVED`로 승인한 뒤 승격했고, 분야 분리 부모·목록 번호 후보 5건은 `REJECTED` 처리했다. CSV에도 검수 상태를 기록했다. V48·V49는 검수된 본 데이터만 추가하며 운영 DB에 새로운 후보 승인 이력을 만드는 마이그레이션은 아니다.

```powershell
.\gradlew.bat test --tests '*ArtsSportsCatalogMigrationTest' --tests '*ArtsSportsCatalogMySqlMigrationTest'
.\gradlew.bat test --tests '*ArtsSportsResearchFieldMigrationTest' --tests '*ArtsSportsResearchFieldMySqlMigrationTest'
```

MySQL 테스트는 Docker의 MySQL 8.0.45 또는 전용 로컬 테스트 DB를 사용한다. 후자를 사용할 때 `SEBU_ARTS_SPORTS_TEST_MYSQL_URL`은 `jdbc:mysql://127.0.0.1:13377/sebu_arts_sports_test`로 제한되며, 별도 `SEBU_ARTS_SPORTS_TEST_MYSQL_USERNAME`·`SEBU_ARTS_SPORTS_TEST_MYSQL_PASSWORD`를 지정한다. 해당 테스트는 전용 DB를 초기화한다.

기존 수집·검수·승격 절차는 [[SEBU 크롤링과 승격]]과 [[SEBU 연구 분야 분류]] 및 아래 공통 흐름 근거 문서를 따른다. 당시 검수 작업은 운영 DB에 직접 실행하지 않았다. V48·V49는 현재 병합된 코드에 포함되어 있으며, 배포 환경의 Flyway 실행 시 미적용 버전부터 순서대로 적용하는 대상이다. 실제 운영 적용은 별도 확인이 필요하다. MySQL DDL은 트랜잭션으로 되돌릴 수 없으므로 충돌로 중단되면 부분 적용 여부를 확인한 뒤 재시도한다.
