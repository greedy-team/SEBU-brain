# SEBU 문서 이전 기록 - 2026-10-08

백엔드의 상세 문서를 [[SEBU 백엔드 문서 모음]]으로 모으고, 코드 저장소에는 실행 코드·테스트·설정·코딩 스킬과 짧은 README를 남기는 변경안이다. PR 머지와 서버 배포는 별도 단계다.

## 이전 범위

- 원본은 [백엔드 develop 21bd49e](https://github.com/greedy-team/SEBU-backend/tree/21bd49e5133210978b4991a99d7e3cb6a33e6a7a)다.
- `docs/`의 Markdown 9개, CSV 1개, 검수 SQL 1개와 README 상세 본문을 보존했다.
- 각 원문에 기존 경로·기준 커밋·해시를 남기고, 문서 링크는 보관함 내부로 연결했다. 실행 명령의 작업 위치는 각 문서에서 확인한다.
- `research-field-category-classification.csv`는 MySQL 마이그레이션 테스트가 읽는다. 백엔드의 `src/test/resources/fixtures/`에도 같은 데이터를 유지하고 테스트의 파일 경로를 옮긴다. 문서 저장소를 clone하지 않아도 BE 테스트가 동작해야 한다.
- 이미 적용될 수 있는 V36 SQL의 옛 `docs/...` 주석은 체크섬 보존 때문에 수정하지 않는다. 코드 경로·DB 스키마·기존 마이그레이션 SQL은 변경하지 않는다.
- 개발용 OOP/SRP·Flyway 스킬은 백엔드에 남긴다. 실제 환경 파일·비밀값·개인 설정을 문서 저장소에 복사하지 않는다.

## 함께 확인한 정책

이전 원문과 요약 노트가 충돌하지 않도록 BE의 추가 2개 커밋을 확인했다. 신규 로그인·복구·갱신으로 발급하는 Refresh 수명은 12시간이며 절대 수명은 최초 로그인부터 30일이다. 기존 14일 토큰은 다음 갱신부터 전환된다. [[SEBU 인증과 CSRF]]

## 반영 순서

1. 이 문서들을 포함한 SEBU-brain PR을 먼저 머지한다.
2. 백엔드 문서 정리 PR을 develop에 머지한다.
3. 팀원은 브레인 저장소에서 `git pull --ff-only`로 받는다.
4. 계획한 main 기반 운영 배포는 main용 배포 구성을 추가한 뒤 별도 코드 머지 절차로 진행한다. 현재 확인한 자동 배포는 develop 대상이며 이 문서 이전으로 배포 방식이 바뀌지 않는다.

실서버·운영 DB는 이 작업에서 변경하지 않는다. 검증 결과는 연결된 PR에서 확인한다.
